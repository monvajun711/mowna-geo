# 《一寸山河》：赛博手搓盆景在线游戏产品与开发蓝图

版本：0.9 · 2026-08-30

## 1. 产品一句话

一款把真实盆景的“养、剪、扎、等”变成可触摸游戏循环的在线创作游戏：玩家从一棵有缺点的素材开始，亲手决定每一次不可逆取舍，跨越季节养成作品，最后由透明的四观评分与流派评审给出展览级报告；也可上传现实盆景照片获得同源评鉴和养护路线。

中文名建议：**一寸山河**。英文副标题：**CYBER PENJING**。核心承诺：**不是捏树外观，而是在时间里做决定。**

## 2. 设计原则

1. **手搓感**：关键步骤都有动作、阻力、声音、风险和结果；不把“修剪”做成菜单按钮。
2. **一剪一因果**：任何动作都能解释为何改变树势、枝序或审美。
3. **美无唯一解**：同一素材至少有两条高分路线；流派不是皮肤，而是不同取舍逻辑。
4. **活着高于好看**：透支树势换来的漂亮会触发健康闸门。
5. **时间是材料**：允许快进季节，但生长、愈合、勒痕和退枝都要结算。
6. **评分可复算**：数值由确定性模型产生，AI 负责证据解释、语言与长期方案。
7. **先做一个完美小循环**：首个版本只做榔榆和两种风格，不以树种数量冒充深度。

## 4. 目标用户与体验层

- **创作玩家**：只想捏出好看的树；提供沙盒、自动养护与柔性评分。
- **系统玩家**：喜欢最优路线和收集；提供树种差异、季节结算、任务与挑战展。
- **盆景爱好者**：要求术语、树性和流派可信；提供专家模式、操作历史和证据评分。
- **现实树主**：上传照片求评；进入“照影评鉴”，明确图像局限与安全建议。

首局 10–15 分钟得到一件“可上展”的数字盆景；长线档案可跨 20 个虚拟年。单次游戏不要求等待现实时间。

## 5. 两个主模式

### A. 手搓盆景

玩家选择素材、正面、风格和目标，在工作台上直接操作。每一季从 3–5 个关键动作中选择，观察树势、风险和审美变化。最终可随时上展，也可继续养。

### B. 照影评鉴

上传 1–6 张现实盆景照片。AI 输出树种候选、证据框、四观 85、流派 15、健康闸门、原创评语和三阶段方案。用户可更正树种/流派/季节后重新计算；更正记录用于改进，不擅自训练。

两个模式共享评分、树种库、流派库、金句库和报告视图。

## 6. 首个可玩版本：榔榆双路线

只做一棵 5 年生榔榆圃地坯，两条目标路线：岭南大树型与当代自然式。

必须完整实现：

1. 旋转观察与选正面。
2. 选择主干延续与第一枝。
3. 剪枝：悬停预览切除区域，按压落剪，切口保留。
4. 蓄养：快进一季，枝长、粗度、芽点、能量变化可见。
5. 牵引或蟠扎：拖动枝条，显示弯曲压力；超阈值预警而非瞬间折断。
6. 浇水/光照：作为复壮与节间控制，不做每日家务模拟。
7. 换训练盆/观赏盆，影响根空间、重心与盆树分。
8. 上展：生成同 Skill 一致的评分报告。
9. 一键观看“从素材到成品”的 20 秒时间线。

竖切片完成标准：新玩家不用教程文字即可剪出第一枝；玩家能说出至少一个“为什么分数变化”的原因；相同存档重复评分差异为 0。

## 7. 核心系统

### 7.1 树图 TreeGraph

树不是静态模型，而是带父子关系的有向图。

```ts
type TreeNode = {
  id: string;
  parentId: string | null;
  kind: 'root' | 'trunk' | 'branch' | 'twig' | 'bud';
  position: [number, number, number];
  direction: [number, number, number];
  length: number;
  radiusBase: number;
  radiusTip: number;
  age: number;
  vigor: number;
  live: boolean;
  scar?: { age: number; closure: number; severity: number };
  wire?: { tension: number; age: number; biteRisk: number };
};
```

每次修剪删除子图并把能量重新分配到保留芽点；蓄养增加长度、半径和分叉；枝位改变影响受光与阴影；伤口逐季闭合。首版不追求植物生理科研模拟，追求规则稳定、因果可见、能被盆景师校准。

### 7.2 形态生成

- 骨架：参数化样条 + 树图。
- 木质：沿样条生成渐缩圆截面；后续可用 WebGL 管线与简化材质。
- 细枝：受树种 `budPattern`、光照、顶端优势和修剪位置控制的受限程序生成。
- 叶片：实例化渲染，叶簇密度由节点活力与季相决定。
- 生长：按季节批量结算，不按每帧模拟。
- 可重放：所有变化存为领域事件，而不是只存最终网格。

### 7.3 健康与能量

关键状态：`vigor`、`rootHealth`、`energyReserve`、`waterBalance`、`stress`、`pestPressure`。健康不是独立血条；它影响芽量、节间、愈合、失枝与叶色。

重要约束：

- `stress > 70` 或 `rootHealth < 45` 时锁定高风险作业。
- 翻盆修根与重剪同季触发协同惩罚。
- 光弱 + 水多降低根健康；光足 + 肥多造成徒长风险。
- 不同树种用配置表改阈值，避免在代码里写死。

### 7.4 评分引擎

最终 100 分：远观势 25 + 中观骨 25 + 近观功 20 + 活观生 15 + 流派校准 15。

在游戏内，以下指标直接从树图计算：重心投影、轮廓占比、负空间分布、根盘径向度、收尖连续性、同点分枝、枝径比、节间分布、交叉遮挡、叶团密度、盆树比例、健康状态、伤口和勒痕。AI 只基于这些证据写解释和匹配评语。

现实图片模式由视觉模型产生同构指标与证据框，再由 `calculate_score.py` 求和、封顶、定级。所有报告保存 rubric 版本。

### 7.5 流派不是滤镜

- 岭南：奖励蓄枝截干过渡、枝托代际、自然大树或清疏画意。
- 扬派：奖励一寸三弯、云片、层次、游龙干势、工稳自然。
- 苏派：奖励古雅老健、粗扎细剪、自然结顶、画意与隽秀。
- 川派：奖励身法、弯拐顿挫、悬根露爪和古雅奇特。
- 徽派：奖励干拙枝巧、藏露、刚劲庄重。
- 海派：奖励扎剪并重、博采而统一、随类赋形。
- 通/如派：奖励两弯半、狮式神态、四面可观与片顶秩序。
- 浙派：奖励刚健气韵风骨、高干合栽或杂木疏朗。

## 8. 任务、经济与长期循环

### NPC 委托

委托不是“做出唯一轮廓”，而是组合约束：树种、预算、健康底线、希望的气质、展台尺寸和期限。例如：“茶馆要一盆清疏、不遮窗、三年内可稳定陈设的榔榆。”

### 展览

展览分素材展、养成展、流派展、自由展。评审同时显示分数和审美分歧：一位重传统，一位重自然，一位重健康；总分仍使用统一引擎，评语视角不同。

### 解锁

解锁的是新选择，不是纯数值升级：更细剪、不同线径、牵引器、训练盆、观赏盆、树种、师门手札、展陈背景。高级工具降低操作误差，不替代设计判断。

### 商业化边界

适合一次性付费或免费竖切片 + 内容扩展。禁止出售影响评分的数值道具；盆器和展陈外观可作为可选内容。玩家上传照片不得默认进入训练集。

## 9. 交互细节与手感

- 剪：刀口贴枝时高亮“保留领口/齐剪/撕裂风险”；落剪有短促阻力、木纤维声和轻微相机回弹。
- 锯：沿切线往复，角度影响切面但不要求像素级精准；评分采用宽容区间。
- 绕线：拖线沿枝自动吸附，玩家控制间距与方向；过密、交叉、过松即时示意。
- 弯枝：显示柔性弧与压力热区，越界先发出木纤维声再进入确认，不突然惩罚。
- 浇水：水先润表面再从排水孔出现；介质不同吸水和排水节奏不同。
- 生长：快进时用可读的芽点—延伸—木质化三段动画，不用一团粒子掩盖结果。
- 撤销：不可逆动作前提供“未来轮廓幽灵”；执行后不提供普通撤销，沙盒可回到季初存档。

## 10. UI 与美术品质标杆

### 视觉方向

不是常见“霓虹赛博朋克”。基调是**漆黑工作台 + 宣纸留白 + 青瓷冷光 + 新芽荧绿 + 火漆橙警示**。赛博感来自扫描线、证据框、树图和时间切片；中国气质来自材质、比例、留白与文字节奏。

色彩建议：

- 墨黑 `#0A0E0B`
- 漆面 `#182018`
- 苔绿 `#B6FF5C`
- 青瓷 `#69D8B4`
- 火痕 `#FF9D5C`
- 宣纸 `#E9F0E5`

字体：标题采用有书卷气的中文宋体/衬线，操作与数值采用清晰黑体；只用两级字重。声音以剪口、木纤维、陶盆、水和风为核心，不用持续轰鸣的电子氛围压过静气。

### 工作台布局

- 中央 65%：树与盆，始终是最大视觉主体。
- 左下：当前工具与三个最相关参数，不放全量属性表。
- 右侧：季节、活力、压力与本回合选择；高级数据折叠。
- 顶部：年份、物候、撤到季初、相机。
- 评分视图：左侧原图与证据框；右侧总分和四观雷达；下方 strengths/weaknesses/不可判、金句、三阶段路线。

### 品质验收

- 每个关键动作具备视觉、声音、触感/动效三种反馈中的至少两种。
- 320px 宽度不丢核心操作；桌面支持鼠标，移动端支持触摸。
- 色彩不作为唯一状态信号；支持减少动态、键盘操作和字幕。
- 首屏 3 秒内可交互；中端手机稳定 45fps，桌面目标 60fps。
- 不复制任何参照游戏的角色、美术、布局或文案。

## 11. 技术架构建议

不要在开工文档中锁死未来版本号；实施时选择当前受支持版本并锁文件。

```text
apps/web                浏览器客户端、工作台、报告视图
packages/domain         TreeGraph、事件、季节结算、风险规则
packages/scoring        四观与流派确定性评分
packages/content        树种、流派、任务、金句数据
packages/renderer       2D/3D 树渲染与交互适配层
services/vision         上传图像→结构化 assessment JSON
services/report         JSON 校验、持久化、分享报告
skills/bonsai-master    本目录 Skill 的发布副本
```

推荐 TypeScript 全栈；前端 React 类框架，渲染层在 WebGL/Canvas 抽象后实现。首个竖切片可用 2.5D 样条与实例叶片，验证玩法后再升级完整 3D。服务端用关系数据库保存用户、树档案、领域事件、评审和授权；对象存储保存图片。上传图片使用短期签名 URL，默认私有。

### 事件溯源

```ts
type BonsaiEvent =
  | { type: 'BRANCH_CUT'; nodeId: string; cutRatio: number; atSeason: string }
  | { type: 'BRANCH_WIRED'; nodeId: string; tension: number }
  | { type: 'SEASON_ADVANCED'; climate: ClimateSnapshot }
  | { type: 'REPOTTED'; potId: string; rootReduction: number }
  | { type: 'PHOTO_ASSESSED'; assessmentId: string; rubricVersion: string };
```

事件可重放、可生成成长视频、可迁移评分版本，也便于定位“为什么这根枝死了”。

### AI 边界

输入视觉模型：原图 + 用户已知信息 + rubric + schema。强制结构化 JSON；温度低；树种候选最多 3；每项分必须关联证据。确定性服务重新求和，拒绝越界值和未知证据 ID。报告明确置信度与不可判项。

高风险养护建议必须满足：树种置信 ≥0.70、用户提供地区与季节、树势无危险闸门；否则只给观察和条件式方案。

## 13. 路线图

### M0 · 规则台（1 周）

把当前知识库导入程序；实现 JSON 校验、评分、金句检索、静态报告。用 20 个手工案例做边界测试。

### M1 · 可玩树（3–5 周）

榔榆 TreeGraph、观察、剪枝、季节生长、基本健康、两种风格评分；无账号本地存档。

### M2 · 手搓质感（3–4 周）

牵引/蟠扎、盆器、声音、预览幽灵、时间线、移动端；完成首局引导与 6 个委托。

### M3 · 照影评鉴（2–4 周）

多图上传、结构化视觉评审、用户更正、报告分享、隐私与限流。

### M4 · 盆房与展览（4–6 周）

账号、云存档、作品图录、主题展、三评委视角、罗汉松与真柏。

### M5 · 内容生产

盆景师合作校准；扩展扬、苏、川、徽、海、通、浙；建立授权图像与专家双评分集。

## 14. 测试与评估

### 评分测试

- 任一子项越界必须拒绝。
- 四观最大值固定 85，流派固定 15。
- `critical` 总分不超过 59，`intervention` 不超过 69。
- 缺图降低置信度，不自动降低艺术分。
- 同一 JSON 重算结果完全一致。
- 更换流派只改变 15 分校准与相应评语，不改四观事实分。

### 专家校准

至少邀请 3 位不同流派实践者对 50 盆授权图片独立评分。比较维度相关性、总分秩序一致性和分歧原因。目标不是消灭分歧，而是让系统能解释分歧来自哪一观、哪一流派权重。

### 游戏测试

- 首局完成率 ≥70%。
- 80% 玩家能正确复述一次操作因果。
- 玩家在两条风格路线之间的选择不低于 30/70，避免伪选择。
- 同局没有“为了刷分必须伤树”的最优策略。
- 对照测试像素级严苛操作与宽容区间；采用更能保留手感而不惩罚设备差异的方案。

## 15. 风险清单

- **审美权威幻觉**：用版本化量表、证据、流派视角和专家分歧降低。
- **树种误识导致伤树**：候选制、置信门槛、高风险建议锁定。
- **模拟过浅**：先完成榔榆完整循环，不堆树种。
- **模拟过重**：只模拟能形成决策的变量；日常维护可自动化。
- **AI 分数漂移**：确定性重算、游戏内几何直算、温度低、版本固定。
- **版权与隐私**：只收授权图；金句全部原创；玩家图默认私有且不训练。
- **美术像参照游戏**：借循环和交互原则，不借具体资产与视觉构图。

> 阅读 `bonsai-vision-master/SKILL.md`、`references/scoring-rubric.md`、`references/game-rules.md`、`references/assessment.schema.json` 和本蓝图。先实现 M0，不做账号、联网视觉模型或完整 3D。创建 TypeScript 项目，导入知识库，完成确定性评分器、金句匹配器、示例 assessment、响应式评分报告页面和单元测试。所有分数必须由子项求和；实现健康封顶与置信区间；流派未知时用 unaffiliated。报告必须显示原图、总分、四观雷达、流派 15 分、证据框、两句金句和三阶段行动。完成后运行测试并提供本地预览。

M0 验收后再发送：

> 在现有项目上实现 M1 榔榆竖切片。使用事件溯源的 TreeGraph；实现旋转观察、选正面、剪枝、季节推进、芽枝增长、活力/压力、岭南与自然式两条评分路线、季初存档和上展报告。不要先做更多树种。每个不可逆动作先显示结果轮廓与风险，且相同事件序列必须产生相同结果。
