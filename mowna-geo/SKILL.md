# 魔女GEO · GEO 实操落地课程

> **一句话信念：GEO 不是「做内容让 AI 看见」，是「让 AI 敢引用你」。**
> SEO 争的是排名和点击；GEO 争的是**在 AI 生成的那一段答案里，你排第几、被怎么描述、附不附你的链接**。

## 这个 Skill 是什么

一套**自带引擎、自带进度、自带证书**的 GEO 实操课程。不是讲概念，是让你亲手把一件事做完：

**让豆包、DeepSeek、文心一言、通义千问、Kimi、元宝（以及 ChatGPT / Perplexity / Google AI Overviews）在用户问到你所在领域时，稳定、正向、准确地提到你。**

### 三件别人做不到、这个 Skill 会做的事

1. **不重不漏**——用 RAG 流程反推出的「AI 六层漏斗」做骨架，26 个关卡严格 MECE（互斥且完全穷尽）。每一层对应 AI 检索链条上一个**独立且必要**的环节，漏一层就断链，做重复就是浪费预算。
2. **进度可见**——`assets/geo-quest/` 下是一个零依赖网页学习台：总体进度条、6 层分层进度、26 关勾选、14 枚徽章、5 个段位、可打印结业证书，数据存本机 localStorage，可导出/导入。
3. **动手有产出**——每一关都有「交付物 + 验收标准」，26 关跑完你手上会有：一份审计过的 robots.txt、一份 llms.txt、一套全站 JSON-LD、一个统一的全网实体档案、一份提示词库、6 类高引用内容模板、一份跑满 30 天的 AI 可见度监测台账、一份 Before/After 对比报告。

## 核心骨架：AI 六层漏斗（GEO-6L）

**为什么是这六层？** 因为所有主流 AI 搜索都跑同一条 RAG 链路，GEO 的优化空间就在这条链路上。六层与链路环节一一对应，天然 MECE：

| 层 | 名字 | 对应 RAG 环节 | 这一层在回答什么问题 | 漏了会怎样 |
|---|---|---|---|---|
| **L1** | 准入层 Access | Crawl 爬取 | AI 爬虫进得来吗？读得到完整内容吗？ | 内容再好，AI 根本没抓过你 |
| **L2** | 解析层 Parse | Ingest 摄取/分块 | AI 读得懂你的页面是什么吗？ | 抓到了但归错类，白抓 |
| **L3** | 实体层 Entity | Entity Linking 实体关联 | AI 认得「你是谁」吗？ | 被当成另一家公司/媒体站 |
| **L4** | 信任层 Trust | Score + 交叉验证 | AI 信你吗？有别人也这么说吗？ | 孤证不立，直接降权 |
| **L5** | 应答层 Answer | Retrieve + Cite | 用户在问的那些问题，你的内容能直接被抽出来当答案吗？ | 有信任但没弹药，答不上 |
| **L6** | 代理层 Agent | Act 行动 | AI 能直接帮你成交/预约/下单吗？ | 被提及但转化断层 |

> **诊断口诀（倒着查，最快定位）**：AI 完全不提你 → 查 L1；提了但归错类 → 查 L2/L3；提到但不被采信 → 查 L4；被信但不被引用 → 查 L5；被引用但不成交 → 查 L6。

## 26 关速览（1 序章 + 6 层 × 4 关 + 1 终章）

### 序章 · 关卡 0：AI 可见度基线诊断（**必做，所有后续都要跟它比**）
跑「3 类中性 query × 6 个平台 = 18 次提问」，截图归档，算出你的初始 **AI 首推率 / 提及率 / 正向占比 / 误述条数**。这是你的 Before。
> 中性 query 三类：① 产业比较型「推荐几家{城市}的{行业}公司」② 主题定义型「什么是{你专精的主题}」③ 品牌搜索型「帮我找{你的品牌}」。

### L1 准入层 · 关卡 1–4
1. **AI 爬虫白名单审计**——robots.txt 逐条放行 8 大 bot（GPTBot / OAI-SearchBot / ChatGPT-User / ClaudeBot / Claude-SearchBot / PerplexityBot / Google-Extended / Bytespider），区分「训练型」与「检索型」。
2. **可渲染性体检**——View Source 测试法，判定 SSR/CSR；AI 爬虫不执行 JS，纯 CSR 站点在 AI 眼里是空壳。
3. **llms.txt + llms-full.txt 部署**——给 AI 一份导航地图（品牌描述 / 核心页面 / 主题分类 / 引用建议）。
4. **可发现性织网**——sitemap + 主题簇内链，让 AI 认定你在某主题上有深度。

### L2 解析层 · 关卡 5–8
5. **Schema.org 类型精准命中**——页面类型 × Schema 类型对照，纠「全站 Article」的典型误用。
6. **JSON-LD 落地与校验**——Organization / Article(BlogPosting) / FAQPage / Product / Service / HowTo / Person / BreadcrumbList 逐条写。
7. **内容分块重构**——问题式 H2 + 首段直答 + 自足 chunk，让每个段落能被单独抽出来当答案。
8. **结构化密度升级**——表格 / 清单 / 参数表 / 定义块 / 日期与来源标注。

### L3 实体层 · 关卡 9–12
9. **实体身份统一（NAP/PQI）**——品牌全称、地址、电话全网零冲突，工商/地图/信用平台反向核验一致。
10. **知识图谱占位**——百科词条、Wikidata、工商信息、行业平台入驻。
11. **地图 POI 认领与校准**——百度/高德/腾讯 + Google Business / Apple Business Connect。
12. **作者与机构实体化**——Person schema + knowsAbout + sameAs，把「人」也变成可被引用的实体。

### L4 信任层 · 关卡 13–16
13. **E-E-A-T / DSS 合规三原则落地**——Data Authenticity / Structured Consistency / Source Diversification。
14. **多源交叉佐证网络**——搭「自有阵地 + 第三方权威 + 行业平台 + UGC 口碑」四层信源矩阵。
15. **原创数据注入**——普林斯顿 GEO 研究验证：原创数据 + 引用来源，引用率提升约 40%。
16. **第三方背书攻坚**——媒体报道 / 垂直平台 / 招投标 / 真实案例的合规获取路径。

### L5 应答层 · 关卡 17–20
17. **提示词（Prompt）调研与词库**——从「找关键词」转向「搜集用户真会问的问题」，建四级词库。
18. **六类高引用内容结构**——答案与定义 / 论证与框架 / 清单与榜单 / 案例与故事 / 对比与纠错 / 权威与专家。
19. **六大中文 AI 平台差异化适配**——豆包 / DeepSeek / 文心 / 通义 / Kimi / 元宝 的信源偏好、时效要求、最佳结构、引用速度。
20. **多模态 GEO**——短视频字幕（豆包重度抓取抖音）、PDF 白皮书（Kimi 偏好）、播客转写、图片 alt 与图表。

### L6 代理层 · 关卡 21–24
21. **AX 评分与 Agent 就绪度**——Crawlability / Structured Data / Content Quality / Agent Interaction / Discoverability / Security 六维自检。
22. **MCP 端点与实时数据**——把目录/库存/价格/预约能力暴露给 Agent（前沿红利位）。
23. **幻觉与误述治理**——AI 说错你时的纠正 SOP，负面信息与误述的处置。
24. **GEO × 私域 × 转化闭环**——AI 推荐流量归因、落地页承接、AI 来源转化追踪。

### 终章 · 关卡 25：GEO 战役 30 天（结业实战）
选定 1 个真实主体（自己的号/店/产品/客户），跑完完整战役，产出 **After 基线**并与关卡 0 对比，提交《魔女GEO 结业战报》。

## 使用方式（三种入口）

### 入口 A：打开学习台（推荐，有进度条/徽章/证书）
```bash
python scripts/deploy.py ./魔女GEO --serve
# 然后浏览器访问 http://localhost:8000
```
或把 `assets/geo-quest/` 整目录复制到任意位置，**双击 `index.html`** 即可（无需联网、无需 npm）。
若浏览器限制 `file://` 下的 localStorage，在该目录执行 `python -m http.server 8000` 后访问 `http://localhost:8000`。

### 入口 B：对话式上课（不开网页也能学）
加载本技能后，直接说：
- 「开始 GEO 课程」→ 从关卡 0 开始，AI 化身 **魔女 GEO 导师**，逐关讲解 + 布置任务 + 验收
- 「我做到第 7 关了」→ 续上进度，讲第 8 关
- 「帮我诊断我的站」→ 跑 L1–L2 快速体检
- 「我的 AI 可见度怎么测」→ 走关卡 0 的 18 次提问 SOP

导师每次回复固定格式：**本关目标 → 你要做的动作 → 交付物 → 验收标准 → 常见坑 → 下一关预告**，并在末尾给出进度条文本。

### 入口 C：命令行自检（技术关专用）
```bash
python scripts/geo_scan.py https://你的域名
```
零依赖（仅 Python 标准库），输出：AI 爬虫放行情况、llms.txt 是否存在、SSR 判定、JSON-LD 类型清单、缺少的关键 Schema、可访问性评分（0–100）与修复建议。对应关卡 1/2/3/5 的验收。

## 教学原则（魔女GEO 的脾气）

1. **先诊断，后开方。** 没跑关卡 0 基线，不许动内容。没有 Before 就没有 After。
2. **每一关必须有实物交付。** 读完不算过，交出文件/截图/链接才算过。
3. **倒着查，别正着补。** 出问题先用诊断口诀定位层，别一上来就写内容。
4. **合规是地板不是天花板。** 所有黑帽手段（虚构 POI、信息投毒、批量同质化内容、刷评、恶意压负面）一律不做——2026 年监管已收紧，且 AI 侧已能识别。
5. **讲人话，去 AI 味。** 内容要能被 AI 引用，先要能被真人读完。
6. **孤证不立。** 2026 年算法的核心变化就是「多源交叉验证」，只发自家一处等于没发。

## 安全与边界

- 本 Skill 是**教学与实操框架**，不对具体排名/引用率做效果承诺；AI 平台算法持续变动，须按季度复测。
- 涉及商标、资质、医疗/金融等强监管行业内容时，须符合《广告法》及行业主管规定，不使用绝对化承诺表述。
- `scripts/geo_scan.py` 仅对你**自己拥有或获授权**的域名发起公开 HTTP 请求，不做任何登录、越权或高频抓取。
- 学习台数据全部存于本机浏览器 localStorage，不上传、无后端、无追踪。
