## 序章

### 关卡 0 · AI 可见度基线诊断（Before）

**目标**：在动任何东西之前，把「AI 现在怎么看你」量化存档。没有 Before，就没有 After，也就没有证书。

**动作**
1. 准备 **3 类中性 query**（每类写 2 条，共 6 条）：
   - ① 产业比较型：`推荐几家{城市}的{行业}{公司/号/店}`、`{行业}做得好的有哪些`
   - ② 主题定义型：`什么是{你专精的主题}`、`{主题}怎么做`
   - ③ 品牌搜索型：`帮我找{你的品牌}`、`{你的品牌}怎么样`
   - ⚠️ **必须是中性提问**，不能写「XX 好吗」这种自证式问题——那测不出真实召回。
2. 在 **6 个平台**各问一遍：豆包、DeepSeek、文心一言、通义千问、Kimi、腾讯元宝（有国际业务再加 ChatGPT、Perplexity、Google AI Overviews）。
3. 每次回答**全屏截图**归档，命名 `Q0_{平台}_{query类型}_{日期}.png`。
4. 填写 `templates/ai-visibility-tracker.csv` 的 Baseline 工作表。

**交付物**
- 截图包（≥18 张，6 平台 × 3 类）
- 填写完成的基线台账

**验收标准**
- 4 项基线数值全部算出：
  - **首推率** = 你在答案中排第 1 的次数 / 18
  - **提及率** = 你被提到的次数 / 18
  - **正向占比** = 正向描述条数 / 被提及条数
  - **误述条数** = AI 说错的关于你的事实条数（地址/业务/名字/年份…）
- 任意一项为 0 或 100%，说明 query 选得不够中性，重选重测。

**常见坑**
- ❌ 用自证式提问（「魔女阿俊的公众号怎么样」）→ 测出来全是好话，毫无意义。
- ❌ 只测一个平台 → 六大平台信源池差异极大，单平台结论会误导整轮策略。
- ❌ 忘了存原始日期 → 30 天后无法证明变化来自你的优化而非算法波动。

**下一关**：L1 关卡 1 · AI 爬虫白名单审计。

## L1 准入层 · Access（AI 进得来吗）

> 这一层最容易被忽略，却是最快见效的。行业审计经验：**robots.txt 误配是出现频率最高的技术问题，约三分之一的站点中招，也是最好修的。** 花 5 分钟审计 robots.txt，期望回报高于写一个月内容。

### 关卡 1 · AI 爬虫白名单审计

**目标**：确保 8 大 AI 爬虫能进你的站，且能读到该读的内容。

**动作**
1. 打开 `https://你的域名/robots.txt`，逐条检查。
2. 复制 `templates/robots.txt`，按你的情况改写。
3. 区分两类 bot，分别决策：
   - **检索型（必须放行）**：`OAI-SearchBot`、`ChatGPT-User`、`Claude-SearchBot`、`Claude-User`、`PerplexityBot`、`Perplexity-User`、`Googlebot`
   - **训练型（按公司政策自选）**：`GPTBot`、`Google-Extended`、`CCBot`、`Bytespider`、`ClaudeBot`
4. 上传后，用 `python scripts/geo_scan.py https://你的域名` 复核。

**关键认知**
- 屏蔽训练型 bot **不会**阻止你被实时引用，但误屏蔽检索型 bot **等于直接放弃被引用**。
- 一刀切全屏蔽已被证实有害：Rutgers / Wharton 研究发现，全面屏蔽 AI 爬虫的发布方流量下降超 23%，且并未减少其他地方的引用。
- robots.txt 只是「对守规矩 bot 的强信号」。已被记录有不声明身份的爬虫不遵守它——重要内容请在服务器层再加规则。

**交付物**：上线后的 robots.txt 文件 + geo_scan.py 的放行报告

**验收标准**
- 6 个检索型 bot 全部显式 `Allow`
- 无 `Disallow: /` 通配误伤
- geo_scan.py 输出「AI 爬虫放行：正常」

**常见坑**
- ❌ 只有 `User-agent: *` 的笼统设置，从没人管过。
- ❌ 早年怕被爬设了整站 `Disallow: /`，把 AI bot 一起挡了。
- ❌ 「我以为 IT 管」「我以为市场管」→ 结果没人管。**这一关必须自己动手验证。**

### 关卡 2 · 可渲染性体检（SSR vs CSR）

**目标**：确认 AI 爬虫拿到的是有内容的 HTML，不是空壳。

**动作**
1. 打开你的页面，**右键 → 查看网页源代码**（注意是 `View Source` / Ctrl+U，**不是**开发者工具 F12）。
2. `Ctrl+F` 搜页面上的一段中文正文。
3. **找得到** → SSR 正常；**找不到** → 纯 CSR，AI 可能读到空壳。
4. 若有国际业务，用 Google Search Console 的 URL 检查工具看「已抓取的 HTML」二次确认。

**关键认知**：绝大多数 AI 爬虫（GPTBot / ClaudeBot / PerplexityBot）**不执行 JavaScript**，只发服务端 HTTP 请求并解析原始 HTML。纯前端渲染（React/Vue SPA 未配 SSR）的站点，在 AI 眼里内容是不存在的——**你花在动效上的预算，AI 一分钱都看不到。**

**交付物**：3 个核心页面（首页 / 一个内容页 / 一个服务或产品页）的 View Source 截图 + 结论表

**验收标准**：3 个页面全部判定为「内容在初始 HTML 中可读」。

**常见坑**
- ❌ 用 F12 检查——F12 显示的是 JS 执行**后**的 DOM，会骗过你。必须用 View Source。
- ❌ Next.js / Nuxt 配错了退化成纯 CSR。可切 SSR 或 SSG 修复。

### 关卡 3 · llms.txt + llms-full.txt 部署

**目标**：给 AI 一份「导航地图」，主动告诉它你是谁、重点页面在哪。

**动作**
1. 复制 `templates/llms.txt`，填写：品牌描述（50–100 字，含公司名/成立年份/核心服务）、核心页面清单、主题分类与代表文章、引用建议。
2. 部署到站点根目录 `https://你的域名/llms.txt`。
3. 进阶：生成 `llms-full.txt`，把重点内容全文内联，减少 AI 的抓取跳数。
4. 技术要求：返回 `Content-Type: text/plain`；设 `Cache-Control: public, max-age=3600`；内容更新时**自动生成**（做成动态路由查库，别手写静态文件，会过期）。

**诚实预期（重要）**
- llms.txt **不是** W3C/IETF 标准，但 Anthropic、Perplexity 已明确支持，Google 在测试。
- 2026 年独立研究显示：主流域名采用率约 **9–10%**，且 GPTBot / ClaudeBot / PerplexityBot 在构建引用时**大多并不主动抓取它**。
- **它今天真正稳定发挥作用的地方是编码智能体**：Cursor、Claude Code、GitHub Copilot 会例行抓取文档站的 llms.txt。
- 结论：**做，但当成半天工期的低成本押注，不要当成流量杠杆。** 对内容型品牌尤其如此。

**交付物**：上线的 llms.txt（+ 可选 llms-full.txt）+ 浏览器访问截图

**验收标准**
- 根路径可访问，返回纯文本
- 四类信息齐全（品牌描述 / 核心页面 / 主题分类 / 引用建议）
- 链接全部 200 可访问

### 关卡 4 · 可发现性织网

**目标**：让 AI 认定你在某主题上有「深度」，而不是只有一两篇散文章。

**动作**
1. 梳理你的内容，按**主题簇（topic cluster）**重组：每个核心主题 1 篇支柱页 + 5–10 篇子页。
2. 子页必须内链回支柱页，支柱页链出所有子页。
3. 更新 XML sitemap，确保支柱页与子页全部收录。
4. 补 `BreadcrumbList` 结构化数据。

**关键认知**：2026 年分析显示，**拥有强内链主题簇的站点，获得的 AI 引用多于内容量相当但彼此孤立的站点**。AI 判断主题权威，看的是「这个域名在这个话题上覆盖了多少相关子问题」。

**交付物**：主题簇地图（可用任意思维导图画出）+ 更新后的 sitemap

**验收标准**
- 至少建成 **2 个主题簇**，每簇 ≥5 篇
- 所有子页有指向支柱页的内链
- sitemap 覆盖全部簇内页面

**🎖 解锁徽章**：`准入钥匙`（L1 四关全通）

## L2 解析层 · Parse（AI 读得懂吗）

### 关卡 5 · Schema.org 类型精准命中

**目标**：别让 AI 把你的服务页误判成媒体文章。

**动作**
对照下表，逐页核对当前 Schema 类型。这张表是这一关的核心：

| 页面类型 | 应使用的 Schema 类型 | 常见误用 |
|---|---|---|
| 公司首页/机构页 | `Organization`（含地址、logo、sameAs）或 `LocalBusiness` | 只标 `WebPage` |
| 服务方案页 | `Service` + `Offer` | 标成 `Article` |
| 产品页 | `Product` + `AggregateRating` | 只有 `Product` 没评价 |
| 案例/作品页 | `CreativeWork` 或 `Article` | 完全没标记 |
| 博客文章 | `BlogPosting`（**不是 `Article`**） | 用 `WebPage` 或 `Article` |
| FAQ 页 | `FAQPage` | 散落各页没整合 |
| 联系页 | `ContactPage` + `ContactPoint` | 只在页脚写纯文字 |
| 教程/步骤类 | `HowTo` | 无 |
| 作者页 | `Person` + `knowsAbout` + `sameAs` | 无 |

**真实教训**：一家健康食品客户，服务页、产品页、案例页全被 SEO 插件默认标成 `Article`，结果 AI 在建索引时把这家公司归成**媒体网站**——用户问「推荐健康食品品牌」时，它根本不在候选名单里。

**交付物**：全站页面 × Schema 类型对照表

**验收标准**：核心页面类型命中率 100%，无「全站 Article」现象。

### 关卡 7 · 内容分块重构

**目标**：让每个段落能被单独抽出来当答案。

**动作**
改写你的 3 篇核心文章，遵循：
1. **每个 H2 写成读者（或模型）真正会问的那个问题**，不要写「产品介绍」「我们的优势」这种。
2. **H2 下面一到两句话内直接给出答案**，背景、前提、例外**放在答案之后**，不要放在之前。
3. 每个 chunk **自足**：一个段落被单独摘出去，仍能完整回答问题，不需要读者回头看上文。
4. 优先使用：清单、表格、步骤、定义块。

**为什么第一点最重要**：这一处编辑对 AI Overview 入选率的贡献，超过几乎任何其他内容改动——因为它精确匹配了这些系统抽取段落的方式：**一个能独立完整回答问题的自足块**。

**交付物**：3 篇改写前后对照（保留原稿）

**验收标准**：任意抽取一个 H2 + 其下首段，能独立回答该 H2 的问题。

---

### 关卡 8 · 结构化密度升级

**目标**：给 AI 更多「可抽取的硬事实」。

**动作**
对每篇核心文章补齐：
- **数据表格**：参数、对比、价格、时间线
- **定义块**：`X 是……` 的显式句式
- **来源标注**：每个数据后附原始出处链接（政府站 / 学术 / 行业报告）
- **日期标注**：`datePublished` + 尤其 `dateModified`（AI 明显偏好 3–6 个月内更新过的内容）
- **图片 alt 与图表说明**：多模态抓取权重在上升，实景图 > 网图

**关键认知**：LLM 不看你的 UI，它解析标题、列表、表格和语义 HTML。**「我们最好」毫无意义，「每天追踪 7 个 AI 模型、150 条提示词」才可引用。** 显式事实 > 暗示语义。

**交付物**：3 篇升级后文章 + 结构化元素清点表（表格数/清单数/外部来源数/日期标注）

**验收标准**：每篇 ≥1 个表格、≥1 个清单、≥3 处带链接的外部来源、明确的更新时间。

**🎖 解锁徽章**：`解析器`（L2 四关全通）

## L3 实体层 · Entity（AI 认得你是谁吗）

### 关卡 9 · 实体身份统一（NAP / PQI）

**目标**：品牌全称、地址、电话在全网零冲突。

**动作**
1. 列出你出现的所有平台，逐项核对 **N**ame（品牌全称）/ **A**ddress（详细门牌）/ **P**hone（联系电话）。
2. 与**营业执照 100% 匹配**，禁止简写、别名、缩写。
3. 检查工商平台（爱企查 / 天眼查 / 企查查）的主体信息：经营范围、注册地址、法人、变更记录，确保无矛盾。
4. 清理全网过期地址、废弃电话、旧 Logo。

**关键认知（2026 年 8 月算法迭代）**
- **PQI 实体校验强化**：企业全称、地址、电话全网必须统一，多版本信息**直接降权**。
- **知识图谱反向核验**：AI 会主动核对工商、地图、信用平台信息是否匹配，**冲突即判定可信度低**。

**交付物**：NAP 全网一致性核对表（≥5 个平台截图比对）

**验收标准**：NAP 一致率 100%。

**🎖 若 ≥5 平台核验全部一致** → 解锁成就徽章 `实体统一者`

### 关卡 10 · 知识图谱占位

**目标**：让 AI 在知识库里有你的「身份证」。

**动作**（按优先级）
1. **合规百科词条**：企业百科、人物百科。内容客观，禁止夸大营销话术。
2. **Wikidata / 维基数据**：有国际业务的必做——这是 Claude、ChatGPT、Perplexity 共用的实体锚点。
3. **工商信息平台**：确保工商、信用公示系统信息准确。
4. **行业垂直平台**：对应行业协会、官方服务平台、招投标平台入驻。

**关键认知**：AI 引用它**能自信识别**的来源。你的品牌名、作者名、核心话题必须**一致地**出现在站内、社交资料与第三方提及中——不能只在你自己的内容里出现。

**交付物**：已建成的实体占位清单（平台名 + 链接 + 状态）

**验收标准**：≥3 个第三方实体占位生效（百科 / Wikidata / 行业平台）。

### 关卡 11 · 地图 POI 认领与校准

**目标**：拿下本地场景的 AI 推荐权重（本地服务刚需）。

**动作**
- **国内三平台**：百度地图、高德地图、腾讯地图——**免费认领商户**（拒绝第三方付费加急代办），严格统一 NAP，定位到**门店正门**（不要定位到马路），上传**门头实拍与店内实景**（拒绝网图），完善经营类目、服务半径、营业时间。
- **境外三平台**：Google Business Profile、Apple Business Connect（覆盖 iOS 端 Siri 与苹果搜索）、OpenStreetMap（提升全球 AI 信源权重）。
- 所有认领截图归档。

**关键认知**：地图 POI 属于**高权重地理信源**，NAP 统一度直接决定本地场景的 AI 推荐优先级。豆包的本地推荐算法中地理权重占比很高（公开资料约 35%）。

**交付物**：≥3 个地图平台的认领成功截图 + NAP 校准前后对比

**验收标准**：国内三平台至少认领 2 个，NAP 100% 匹配执照。

### 关卡 12 · 作者与机构实体化

**目标**：把「人」也变成可被引用的实体——这是个人 IP 的胜负手。

**动作**
1. 建作者页：`Person` schema，含 `knowsAbout`（你专精的话题数组）、`sameAs`（微博/知乎/公众号/GitHub/LinkedIn 等已验证主页）。
2. 每篇文章署名，链接回作者页。
3. 作者页写清：真实从业年限、可验证的履历、一手经验证据。
4. 机构同理：`Organization` 的 `sameAs` 补全。

**关键认知**：E-E-A-T 的「可验证」是关键。**AI 不看你自称多厉害，看的是页面上有没有可验证的信号。** 原作者署名 + 更新日期 + 外部权威引用 + 一手案例数据，四件套缺一不可。

**交付物**：作者页上线链接 + Person JSON-LD 代码

**验收标准**：作者页可被索引，`knowsAbout` ≥3 个话题，`sameAs` ≥3 个已验证主页。

**🎖 解锁徽章**：`实体之印`（L3 四关全通）

## L4 信任层 · Trust（AI 信你吗）

### 关卡 13 · E-E-A-T / DSS 合规三原则落地

**目标**：把信任从形容词变成可核查的清单。

**动作**：逐项自检并落地 **DSS 三原则**（2026 年 E-E-A-T 的升级版）：

| 原则 | 含义 | 落地动作 |
|---|---|---|
| **D** — Data Authenticity 数据真实可溯源 | 禁止虚构业务、伪造 POI、虚假资质 | 页面上每个数字都能指出处 |
| **S** — Structured Consistency 结构化信息全网一致 | NAP、主体信息零冲突 | 关卡 9 的产出复用 |
| **S** — Source Diversification 多源独立信源背书 | 避免单一渠道内容堆砌 | 关卡 14 的目标 |

再加 **E-E-A-T 四签名**（B2B / 个人 IP 必做）：
1. **作者署名**——每篇内容有作者或公司全名，链接到作者页
2. **更新日期**——不止创建日期，必须有最后更新日期
3. **外部引用**——引用权威资料（政府站 / 学术 / 行业报告）并附原始链接
4. **案例数据**——「根据 24 年、3000+ 客户实际数据」胜于「我们经验丰富」

**交付物**：DSS + E-E-A-T 自检表（逐条打勾，附证据链接）

**验收标准**：7 项全部落地且有页面证据。

### 关卡 18 · 六类高引用内容结构

**目标**：掌握 AI 最偏爱的六种内容骨架。

**动作**：对每类各写 1 篇（共 6 篇），模板见 `references/04-content-weapons.md`。

| 模式 | 何时用 | 为什么 AI 爱它 |
|---|---|---|
| **① 答案与定义型** | 「X 是什么」 | 直接对应定义型 query，抽取成本最低 |
| **② 论证与框架型** | 建立思想领导力 | 结构化、可复述、易被当成方法论引用 |
| **③ 清单与榜单型** | 「最好的 X」「X 有哪些」 | **收获最高 AI 引用率的格式** |

### 关卡 19 · 六大中文 AI 平台差异化适配

**目标**：同一份内容，按平台口味改写。**一刀切的 GEO 策略必然失败。**

**动作**：先读 `references/02-platform-playbook.md`，然后按平台改写关卡 18 的 6 篇内容，至少覆盖 3 个平台。

速查（详见 02 号文件）：

| 平台 | 生态偏袒 | 最佳内容结构 | 时效要求 | 引用速度 |
|---|---|---|---|---|
| **豆包** | 字节系（头条 35.2%、知乎 21.8%、抖音 13.5%），超 60% 素材来自自有平台 | FAQ 问答 + 列表对比；**短视频字幕** | 1–2 周内 | 4–7 天（最快） |
| **DeepSeek** | **无生态偏袒**，CSDN 24.6%、知乎 19.8%、博客园 15.3%，以技术深度为唯一标准 | 参数表 + 代码块 + 架构图；5000 字以上深度长文 | 无明确期限 | 15–30 天 |

| **通义千问** | 阿里系（搜狐号 28.7%、网易号 19.3%、知乎 14.1%）+ 电商场景 | 表格 + 列表 + 模块化；产品对比、购买决策内容 | 6 个月内 | 10–18 天 |

| **腾讯元宝** | 微信生态（公众号 40%+）、搜狗百科、新闻媒体 | 列表式 + 问答式 | 6 个月内 | 7–14 天 |

**关键认知**：六个模型的引用偏好差异显著——DeepSeek 偏好数据 + 逻辑，豆包偏好生活化场景，Kimi 偏好深度长文，文心偏好百度生态信源。**一套内容打天下必然在部分模型中失效。** 且单模型覆盖有算法波动风险：一旦该模型大版本更新，你的 AI 出现率可能断崖下跌。

### 关卡 20 · 多模态 GEO

**目标**：拿下 2026 年权重上升最快的部分。

**动作**
1. **短视频**（豆包核心）：抖音是豆包的重要信源（引用率极高）。做品牌介绍 / 产品测评 / 行业知识 / 客户案例四类短视频。**字幕与描述中自然嵌入核心关键词**——AI 通过字幕提取文本。

**验收标准**：三类素材各 ≥1，视频字幕含核心关键词，PDF 可被公开检索到。

## L6 代理层 · Agent（AI 能替你成交吗）

> 这一层是 2026 年最前沿、也是竞争最小的位置。传统电商 KPI（会话、跳出率、CPC）在这里几乎失效。

### 关卡 21 · AX 评分与 Agent 就绪度

**目标**：量化你的站点对 AI 智能体的友好程度。

**动作**：按 6 个维度自检打分（各 0–100，取均值）：

| 维度 | 检查什么 |
|---|---|
| **Crawlability 可爬性** | robots.txt 放行、sitemap、无 JS 依赖 |
| **Structured Data 结构化数据** | Organization / Product / Service / FAQ 完整度 |
| **Content Quality 内容质量** | 自足 chunk、显式事实、来源标注、新鲜度 |
| **Agent Interaction 智能体交互** | 是否有机器可读的动作入口（预约/询价/下单） |
| **Discoverability 可发现性** | llms.txt、主题簇、多平台实体一致 |
| **Security 安全** | HTTPS、无注入风险、权限边界清晰 |

**关键认知**：智能体只推荐 **1–3 个选项**，不是 10 条蓝链。**没被智能体优化，你得到的不是曝光减少，而是归零。** 但好消息是：这是一片**公平的战场**——多数大企业还没做，先动手的小玩家今天就能赢过没动手的行业巨头。

**交付物**：6 维评分表（当前分 / 目标分 / 差距项）

**验收标准**：6 维全部完成打分，且识别出 ≥3 个最高杠杆差距项。

### 关卡 22 · MCP 端点与实时数据（前沿红利）

**目标**：从「被静态抓取」升级为「被实时调用」。

**动作**（按可行性选择）
1. **评估**：你的业务是否数据密集（价格、库存、档期、预约、目录）？是 → 值得做；否 → 跳过，把精力放回 L5。
2. **落地**：把核心数据通过 API 暴露，并提供 MCP 服务端点，让支持 MCP 的智能体（如 Claude 系）能**直接查询**而非爬页面。
3. **文档**：技术文档与 API 文档本身要做 GEO——编码智能体（Cursor / Claude Code / Copilot）会例行抓取文档站的 `llms.txt`。

**关键认知**：MCP 是 Anthropic 提出（2024 年末）的开放标准。启用 MCP 的智能体**不再只依赖静态网页**，而是连接实时 API 直接从品牌侧取数。能提供 MCP 服务端的品牌，会获得 **「实时数据源」的优先定位**。这是目前投入产出比最高的前沿卡位。

**交付物**：MCP 可行性评估结论（做/不做 + 理由）；若做，提供端点文档链接

**验收标准**：评估结论有明确理由；若执行，端点可被公开发现且文档可被编码智能体抓取。

### 关卡 23 · 幻觉与误述治理

**目标**：AI 说错你的时候，能修。

**动作**
1. **复测**：重跑关卡 0 的 18 次提问，列出所有**误述**（地址错、业务错、名字错、年份错、把别人家的事安在你头上）。
2. **溯源**：误述通常来自三个地方——① 你自己的旧信息没清理 ② 第三方错误信息 ③ 模型把同名实体混淆。**先定位来源再动手。**
3. **处置 SOP**：
   - 源头是**自己** → 更新所有平台的 NAP 与业务描述（回到关卡 9）

⚠️ **绝对禁止**：恶意压制负面、抹黑竞品属于不正当竞争；批量伪造内容属于信息投毒，均为整治重点。参见 `references/06-compliance-redlines.md`。

**交付物**：误述清单（含来源判定）+ 处置记录 + 复测对比

**验收标准**：误述条数较基线下降，且处置过程 0 次触碰合规红线。
